上一篇文章中我们写到了 var 声明的变量会存在变量提升的内容，正是由于 JavaScript 存在变量提升这种特性，从而导致了很多与直觉不符的代码，这也是 JavaScript 的一个重要设计缺陷。ES6 中为了解决这种非线性的缺陷写法，引入了块级作用域并配合 let、const 关键字食用，来避免这种设计上的缺陷。

## 1、作用域

作用域：是指在程序中定义变量的区域，该位置决定了变量的生命周期。换句话说作用域就是变量与函数的可访问范围，即作用域控制着变量和函数的可见性和生命周期。

我们在 ES6 之前，JavaScript 只支持全局作用域和函数作用域：

- **全局作用域**：对象在代码中的任何地方都能访问，其生命周期伴随着页面的生命周期。
- **函数作用域**：在函数内部定义的变量或者函数，并且定义的变量或者函数只能在函数内部被访问。函数执行结束之后，函数内部定义的变量会被销毁。

但是其他的语言普遍是存在块级作用域的，块级作用域是使用一对大括号包裹的一段代码，比如函数、判断语句、循环语句，甚至单独的一个 `{}` 都可以被看作是一个块级作用域。

看一个 C 语言代码的例子：

```c
char* myName = "joinmouse";
void showName() {
  printf("%s\n", myname);
  if(0){
    char* myname = "demo";
  }
}
int main() {
  showName();
  return 0;
}
```

上面的例子中，最终打印的结果是全局变量 myName 的值，之所以这样，是因为 C 语言是支持块级作用域的，所以 if 块里面定义的变量是不能被 if 块外面的语句访问到的。

和 Java、C/C++ 不同，ES6 之前是不支持块级作用域的，因为当初设计这门语言的时候，并没有想到 JavaScript 会火起来，所以只是按照最简单的方式来设计。没有了块级作用域，再把作用域内部的变量统一提升无疑是最快速、最简单的设计，不过这也直接导致函数中的变量无论是在那里声明的，在编译阶段都会被提取到执行上下文的变量环境中，所以这些变量在整个函数体内部的任何地方都是能被访问的，这也就是 JavaScript 中的变量提升。

### 2.2、本应销毁的变量没有被销毁

```javascript
function foo() {
  for(var i = 0; i < 7; i++) {
  }
  console.log(i)
}
```

如果使用的是其他语言如 C，那么 for 循环结束的话，i 就应该被销毁了，但是在 JavaScript 代码中 i 的值并没有销毁，最后打印的是 7。

这同样也是由变量提升而导致的，在创建执行上下文阶段，变量 i 就已经被提升了，所以当 for 循环结束之后，变量 i 并没有被销毁。

## 3、let 和 const 如何解决变量提升的缺陷

let 和 const 使得 JavaScript 也能像其他语言一样拥有了块级作用域。

let 和 const 的区别是：使用 let 关键字声明的变量是可以被改变的，而使用 const 声明的变量其值是不可以被改变的。

```javascript
let x = 5
const y = 6
x = 7
y = 9 // 报错，const 声明的变量不可以修改
```

我们通过上面的例子可以看到使用关键字 let 更符合我们的编程直觉：作用块内声明的变量不影响块外面的变量。

```javascript
// var
function varTest() {
  var x = 1;
  if (true) {
    var x = 2;  // 同样的变量!
    console.log(x);  // 2
  }
  console.log(x);  // 2
}
// let
function letTest() {
  let x = 1;
  if (true) {
    let x = 2;  // 不同的变量
    console.log(x);  // 2
  }
  console.log(x);  // 1
}
```

## 4、JavaScript 如何支持块级作用域的

我们已经知道 JavaScript 引擎是通过变量环境实现函数级作用域的，那么 ES6 又是如何在函数级作用域的基础之上，实现对块级作用域的支持呢？先查看下面的代码：

```javascript
function foo(){
    var a = 1
    let b = 2
    {
      let b = 3
      var c = 4
      let d = 5
      console.log(a)
      console.log(b)
    }
    console.log(b)
    console.log(c)
    console.log(d)
}
foo()
```

### 1、编译并创建执行上下文

因为 c 使用 var 赋值的，因此会存在变量提升；这里的词法环境有些地方有称之为静态作用域，实际上 `let b` 的阶段分为 2 部分：一部分是创建 b，另外一部分是初始化 b 的值为 undefined，暂时我们只用记住这个就好了；同时我们会发现函数作用域内部，通过 let 声明的变量并没有被放到词法环境中去。

### 2、执行代码

执行代码块，变量环境中 a 的值已经被设置成了 1，词法环境中 b 的值已经被设置成了 2。

进入函数的作用域时，作用域块中通过 let 声明的变量，会被存放在词法环境的一个单独的区域中，这个区域中的变量并不影响作用域块外面的变量，比如在作用域外面声明了变量 b，在该作用域块内部也声明了变量 b，当执行到作用域内部时，它们都是独立的存在。

## 5、创建、初始化以及赋值

我们先看一个例子：

```javascript
let myname = 'demo1'
{
  console.log(myname)
  let myname = 'demo2'
}
```

我们来分析下这块会打印出什么，相比有些人会觉得是 'demo1'，因为块作用域的 `let myName` 还未被声明，那么真实的是这样的嘛？

我们复制上面的代码在 Chrome 控制台中运行发现报错如下：myName 在初始化之前不被允许访问，那么这到底是怎么回事呢？

还记得我们前面提到 let 申明变量分为创建和初始化阶段嘛，我们这里可以将 `let myName = 'demo2'` 分为三个阶段：第一个阶段是创建变量 myName，第二个阶段是初始化变量 myName 为 undefined，第三个阶段就是赋值阶段 `let myName = 'demo2'`。

接下来上面的报错我们就很好理解了，当进入块级作用域的时候，我们其实 myName 已经被创建了，但是由于没有初始化所以出现了上面的报错。换句话说 let 申明的变量被提升了，但是只提升了创建的阶段，初始化阶段并没有提升，在初始化之前使用变量，就会形成一个暂时性死区。

接下来我们对比下 var 的申明阶段，其实是提升了变量的创建+初始化阶段；那么函数声明的提升，则是提升了创建+初始化+赋值三个完成的阶段。
