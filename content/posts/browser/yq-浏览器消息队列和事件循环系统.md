## 1、宏任务和微任务

### 1.1、宏任务

其实宏任务就是指的消息队列中等待被主线程执行的事件(任务)，每个宏任务在执行时，浏览器的 JS 引擎(以 V8 为例)会创建一个 JS 的执行栈，去执行 JS 代码，当该宏任务执行结束时，整个栈又会被清空，接着主线程继续执行下一个宏任务。

### 1.2、微任务

微任务我们可以将其理解为一个异步执行的函数，它的调用时机是在主函数执行结束之后，当前的宏任务执行结束之前。

上面的描述有点抽象，之前在浏览器消息队列和事件循环系统中写过 JavaScript 之所以要引入微任务，主要是主线程执行的消息队列中宏任务的时间颗粒比较大，无法胜任一些对精度和实时性要求较高的场景，那么微任务可以在实时性和效率之间做一个有效的权衡。同时微任务(如 Promise)相较于宏任务，赋予了开发者控制其调用执行的时机，改变我们的异步编程模型，从而使得我们可以使用同步的代码(async/await)编写异步的调用。

## 2、微任务的上下层知识栈

通常我们知道微任务(以 Promise 为例)上层所衍生的 Promise、Generator、协程、await/async 等现代前端经常使用的一些技术，但是更重要的是我们需要对微任务的下层消息队列、主线程还有调用栈需要有更深的理解，才能更好的去掌握上层的知识。

## 3、主线程、调用栈、消息队列

### 3.1、主线程和调用栈

调用栈是一种栈的数据结构，用来管理主线程上执行函数的调用。

1、JS 引擎执行上面这段代码，首先将全局执行上下文压入调用栈：

```javascript
function bar() {
}
foo(fn) {
  fn()
}
foo(bar)
```

2、执行 foo 函数，创建 foo 函数的执行上下文，并压入栈中

3、foo 函数中调用了 bar 函数，执行 bar 函数的时候先创建 bar 函数的执行上下文

4、bar 函数执行结束，JS 引擎会将栈中的 bar 函数执行上下文 pop 出来

5、foo 函数执行结束，JS 引擎将 foo 函数执行上下文从栈中 pop 出来

### 3.2、主线程、调用栈和消息队列

还是从一个例子说起：

```javascript
function foo() {
  foo()
}
foo()
```

这段代码我们都知道会发生栈溢出(爆栈)。

那我们对上面的代码进行改造下：

```javascript
function foo() {
  setTimeout(foo, 0)
}
foo()
```

我们将 foo 函数内同步的调用改成了 setTimeout 异步的调用，那么还会发生栈溢出嘛？

答案是不会的，我们来分析下这段代码：每次遇到 setTimeout 的时候里面的 foo 会被封装成一个宏任务，放到消息队列中，然后主线程再按照一定的规则循环的从消息队列中去读取下一个任务。

1. 主线程开始执行上面的代码(一个宏任务)
2. 执行 foo 函数，创建 foo 函数的执行上下文
3. foo 函数执行 setTimeout 时，会将 foo 函数封装成一个新的宏任务并添加到消息队列中
4. foo 函数执行结束，主线程结束当前宏任务，调用栈被清空
5. 当前的宏任务结束后，主线程去消息队列中去取下一个宏任务，而刚才通过 setTimeout 封装的回调 foo 函数作为宏任务，在某个时刻也会被主线程取出并执行
6. 重复上面的过程，但调用栈并不会发生栈溢出的情况

## 5、微任务解决了宏任务时机不可控的问题

在上面我们其实就写到过微任务相比于宏任务，我们可以控制其调用的时机。这里我们还是先说下宏任务吧，上面的例子中我们知道通过将函数封装成宏任务来解决的栈溢出的问题，但是被封装的宏任务需要先放到消息队列中，如果排在消息队列比较靠后的地方，前面的宏任务执行时间又比较长，那么就会影响到这个被封装的宏任务执行，而且这个影响是不可控的，简单的说我并不知道前面的宏任务需要多久才可以执行。

JavaScript 引入微任务，微任务的执行时机是在主函数执行之后，当前的宏任务执行结束之前，这样作为开发者就可以比较精准的去控制回调函数的执行时机了。

JS 引擎(V8 为例)会为每个宏任务维护一个微任务的队列。当执行一段 JS 代码的时候，就会为这段代码去创建一个环境对象，微任务队列存放在这个环境对象中。如 Promise.resolve 会生成一个微任务放入微任务队列中，等到这段代码块执行结束的时候，就会去从微任务队列中去取去执行，然后环境对象被销毁，进入下一轮的循环。

关于微任务的执行时机，我们主要知道的是：

- 首先，当前任务中产生一个微任务，通过 Promise.resolve() 或 Promise.reject() 都会触发微任务，触发的微任务不会在当前的函数被执行，因此执行微任务时，不会导致栈的无限扩张
- 其次，和异步调用不同的是，微任务会在当前任务结束之前执行，这就是当前微任务执行结束之前，消息队列中其他任务是不可能被执行的

执行分析如下：

```javascript
function bar() {
  console.log('bar')
  Promise.resolve().then(
    (str) => console.log('micro-bar')
  )
  setTimeout((str) => console.log('macro-bar'), 0)
}

function foo() {
  console.log('foo')
  Promise.resolve().then(
    (str) => console.log('micro-foo')
  )
  setTimeout((str) => console.log('macro-foo'), 0)
  bar()
}

foo()
console.log('global')
Promise.resolve().then(
  (str) => console.log('micro-global')
)
setTimeout((str) => console.log('macro-global'), 0)
```

1. 全局上下文压栈，微任务队列创建
2. 执行 foo 函数，微任务队列中放入 micro-foo，消息队列中放入宏任务 macro-foo
3. foo 函数中调用了 bar 函数，微任务队列中放入 micro-bar，消息队列中放入 macro-bar
4. 执行全局的 Promise
5. 先取微任务队列中所有的任务执行，然后再从消息队列中取宏任务执行

输出结果：

```javascript
// 输出
foo
bar
global
// 微任务队列
micro-foo
micro-bar
micro-global
// 消息队列 (宏任务)
macro-foo
macro-bar
macro-global
```

需要注意的是微任务如果循环的执行微任务，那么会导致消息队列中其他的任务被延迟执行，因此开发的时候也需要注意这一点。
